# Genius — 生存战争守护灵

住在《生存战争》（Survivalcraft）里的 AI 同伴。按 G 键打开对话窗，用平常的话告诉它要做什么，它自己定计划、动手干活，并把结果说给你听：挖矿、盖房、种田、打猎、跟随、搬东西。

当前版本 **v0.13.0**。

> 罗马神话中，*genius* 是伴随每个人一生的守护灵，与 *numen*（神意）同属一脉。
> 本项目受 Minecraft 模组 [Numen](https://github.com/Dwinovo/minecraft-numen) 启发，面向 Survivalcraft 用 C# 重新实现。
> 寻路等部分参考了 Numen / Baritone 的算法设计，按生存战争自己的机制重写；
> 另有四处代码移植自两个已获作者授权的生存战争模组，见下方“第三方来源”。

## 它是怎么工作的

守护灵分成两半：

- **大脑**是一个大语言模型（下文简称“模型”）。它听你说话，决定下一步该做什么。
- **身体**是游戏里一个人形角色。模型不能直接操纵它，只能调用一组“工具”，例如“走到某处”“挖这个矿”“盖一间房”。每个工具都是写死在模组里的一段确定流程，做完把成功或失败的原因回报给模型。

模型后端可以是任何兼容 OpenAI 接口的服务，地址、密钥和模型名在游戏内设置页填写，只存在本机。

## 能做什么

v0.13.0 一共 37 个工具（清单以 `src/SurvivalcraftGenius/Mod/Tools/GeniusToolTable.cs` 为准）：

| 类别 | 工具 | 说明 |
| --- | --- | --- |
| 说话与查资料 | `say`、`query_recipes`、`query_help`、`read_knowledge` | 回话；查游戏里的真实配方；搜游戏自带的帮助；读本地攻略文件夹（玩家可以自己往里放攻略） |
| 计划与任务 | `todowrite`、`task_status`、`task_stop` | 记任务清单；查正在做的事做到哪；叫停 |
| 观察 | `scan_surroundings`、`look_around`、`get_inventory`、`find_blocks`、`find_build_site`、`list_waypoints` | 扫描方块和生物；画一张文字俯视图；看背包；按名字找方块；给房子或田选址；读“旅行地图”模组的路标 |
| 移动 | `goto`、`follow_player`、`descend_to`、`teleport` | 走到坐标（可以挖穿障碍）；跟随；挖螺旋楼梯下到矿层；传送 |
| 干活 | `dig_block`、`place_block`、`mine_resource`、`craft`、`smelt` | 挖一格、放一格；一句话完成整趟挖矿；合成；熔炼 |
| 种田 | `till_soil`、`plant_seed`、`fertilize`、`use_bucket`、`harvest_crops`、`tend_farm` | 翻地、播种、施肥、用桶装水倒水、收割；`tend_farm` 开启后一直自己看田 |
| 盖房 | `build_shelter`、`build_prefab`、`list_prefabs` | 按尺寸盖一间房；按预制图纸盖（内置窝棚、小屋、木屋）；列出图纸和所需材料 |
| 物品 | `collect_items`、`take_from_chest`、`put_into_chest`、`give_to_player`、`equip_tool` | 捡掉落物、开箱取放、交给玩家、换手持工具 |
| 战斗 | `attack` | 指定目标后由身体决定近战还是用弓 |

另外有一层不经过模型的“本能”：掉进岩浆会逃、溺水会上浮、着火会找水、被打会还手。

联机时，模型和对话记录留在玩家自己的客户端，身体的动作在服务端执行。这部分代码已完成，但两台机器的实机验证还没做（见 [docs/ROADMAP.md](docs/ROADMAP.md) M4）。

## 设计原则与机制

下面每条都写了规则、关键数字，以及为什么这样定。数字出自当前源码，理由出自提交记录和 `docs/` 下的设计文档。

### 1. 同伴只做玩家做得到的事

守护灵挖方块按游戏真实的挖掘耗时算，会自动换上背包里最快的工具，工具会磨损；合成要查真实配方，三格宽的配方要旁边有工作台，熔炼要有熔炉和燃料。它没有瞬间破坏、凭空造物之类的能力。

“AI 同伴只做玩家做得到的事”写在 v0.12 计划里（[docs/PLAN-v0.12.md](docs/PLAN-v0.12.md) D3），下面的传送限制就是按这条定的。

### 2. 有唯一正确答案的动作，不经过模型

拿免费的纯状态机模组“工具人”做对照后数了一遍：前四次试玩的十三条抱怨里，只有两条是模型想错了，其余全是身体不听使唤。于是定下分工（[docs/ROADMAP.md](docs/ROADMAP.md) M5）：凡是有唯一正确答案的动作，都写成身体里的确定流程；模型只负责“定目标”和“出了预料之外的事怎么办”。

理由有两层。一是经过模型就可能跑偏。二是每经过一次就是一次费用：模型每走一步都要把系统提示词和全部工具说明重发一遍，2026-08-11 实测每步约一万两千 token，其中约四千四是中转服务固定加上的、改不掉，能减少它的办法只有少走几步（[docs/TOKEN-COST.md](docs/TOKEN-COST.md)）。

几个直接的结果：

- `mine_resource` 是一次调用完成整趟远征：找矿（水平 24 格、向下 28 格内）、挖过去、采、捡、原路返回。途中死了会复活、回去捡东西、接着挖，死满三次才放弃。
- `tend_farm` 只需要模型开一次（顺便定种什么、管多大范围，默认半径 12 格），之后身体自己循环：捡掉落、收熟的、补种空地，不再花模型的步数。玩家任何新指令都会立刻顶掉它。
- `attack` 只让模型指定目标，不让它选武器。距离、有没有视线、还剩几支箭，都是模型下指令那一刻看不到的，所以由身体到跟前再决定。

### 3. 缺工具时的顺序：翻箱子 → 采集 → 合成 → 最后才向玩家要

系统提示词里写死了这个顺序：先看自己背包；再扫描附近的箱子去取；再自己采集和合成（没有镐就砍木头 → 木板 → 木棍 → 配鹅卵石做石锤）；都不行才开口，并且要说清楚到底缺什么。

配套有一道“工具太弱就不硬挖”的门槛：按手头工具算，挖一格超过 **16 秒**才拒绝。这个数最初是 6 秒，结果把游戏本身设计好的起步路线也挡住了：徒手挖花岗岩要 14 秒，而“徒手挖一块石头做第一把石锤”正是起步方式，于是它陷入“要工具才能拿到石头，要石头才能做工具”的死循环，只能向玩家讨一块石头（playtest 4）。门槛改到 16 秒后，徒手挖石头放行，徒手挖铁矿、钻石矿（22 秒）仍然拒绝并告诉它先做石锤。

### 4. 传送：60 秒冷却、20 格以内不传；玩家亲口要求时不受限

| 规则 | 数值 |
| --- | --- |
| 两次传送的最短间隔 | 60 秒 |
| 最短传送距离 | 20 格，更近就走过去 |
| 玩家亲口要求传送 | 两条限制都跳过 |
| 仍然拒绝的情况 | 落点紧挨岩浆，或在玩家建筑的方块里 |

早期的传送没有任何代价，工具说明里还把它写成“下矿层最快的办法”。结果模型把它当交通工具用，寻路的毛病全被传送盖住，一直暴露不出来；这也不符合第 1 条原则。v0.12.0 加了冷却和最短距离，计划里的原话是“不删功能，删的是它的免费”。

随后的 playtest 16 里，玩家连打三次“传送到我这里”，又补了一句“我说的是传送”，每次都被拒绝，先是因为太近，后来是因为冷却。两条限制本来是为了管住模型，不是为了驳回玩家的直接指令，所以 v0.12.1 加了 `player_asked` 参数：玩家亲口要求时两条都不算。

### 5. 任务清单：让它记得做到哪一步

在 `todowrite` 出现之前，守护灵手里没有“计划”这个东西，每一步都要从聊天记录里重新推断“我在干什么”。任务被打断、被顶替、超时或者玩家死亡之后，它只能靠猜；猜错了就从头再来，在游戏里看起来就是原地转圈。playtest 11 到 15 反复抱怨的正是这个。

现在的规则：

- 只有包含好几件独立交付物的大活才写清单（例如“建个基地：房子加农田”）；一个工具就能做完的事不写。
- 模型每次提交整张清单，最多 20 项；同时最多一项“进行中”；**已完成的项不能改回未完成**，否则会永远重做做完的活。
- 清单每回合都会放进模型的输入，并随世界保存。
- 长任务可以用 `task_status` 查进度、`task_stop` 叫停；同一回合里重复派发同一件活会被拒绝，因为那等于把它从零重启（playtest 15 里一栋房就这样被自己顶掉了三次）。玩家改主意派的新活则直接替换旧活。

### 6. 盖房：整张图纸一次盖，墙和屋顶从屋外放

- **一张图纸一次盖完。** 早期是模型一格一格地调用 `place_block`，playtest 10 里盖一间房调用了 107 次（[docs/TOKEN-COST.md](docs/TOKEN-COST.md)），每次都是一轮模型往返，坐标还会记错，盖出来零碎又悬空。现在先勘察地形，再一次算出完整图纸：地基逐列填实（保证不悬空）→ 掏空 → 四面墙 → 门洞 → 屋顶。地不平会先整地。
- **墙和屋顶一律从屋外放。** playtest 14 里玩家三次说“你一直在你盖的房子里转圈圈”。原因是图纸顺序让它站在屋里砌墙、盖顶，把自己封死在里面；它传送出去之后，下一次调用又从门洞走回屋里。现在地基和掏空仍在里面做（那时还没有墙），之后每一格都从房子占地范围以外的站位去放。
- **按真实结果汇报。** playtest 12 里它一块没放，却报告“盖好了一间 5×5 的房子”，因为汇报是照着图纸念的。现在零块就说没盖起来，不全就说只盖了一部分。
- **半成品可以续建。** 给了坐标时，图纸上该是实心、现在已经是人造方块的格子达到 8 格，就判定为续建，直接补齐。
- **预制图纸把“设计”移出模型。** 每次让模型现场设计，房子的样子忽好忽坏。内置窝棚、小屋、木屋三张图纸，`list_prefabs` 会把每张图纸的材料清单和背包里现有的数量对照着列出来。窝棚是 4×4、不用玻璃，为的是第一晚就盖得起。

### 7. 打鸟：改身份、用弓、算提前量

连续五次试玩都反馈“还是打不到鸟”。原因有两层，分两次解决：

1. **潜行从一开始就不可能成功。** 查游戏源码发现，鸟只要看到正前方约 14 格内有“捕食者”就起飞，跟脚步声、潜行、蹲下都没关系；而守护灵的生物类别恰好被算作捕食者。按玩家的提议，把它的类别从“其他陆地生物”改成“鸟”（v0.11.5），鸟就不再因为看见它而飞走。副作用逐条查过：熊、狼这些猛兽照样会攻击它。
2. **天上的鸟近战够不着。** v0.13.0 加了弓，瞄准时解一道弹道题：鸟在动，箭在下坠，直接对着鸟射会从两个方向各偏一次，所以要算提前量。

| 弓的参数 | 数值 |
| --- | --- |
| 箭速 | 28 格/秒（游戏引擎的值） |
| 用弓的距离 | 4～30 格；4 格以内改近战 |
| 偏好的站位距离 | 12 格 |
| 两箭间隔 | 1.5 秒 |

没有弓、解不出弹道或目标太近时退回近战。弹道解算移植自“铁器风云”，开弓逻辑移植自“工具人”（见“第三方来源”）。

### 8. 种田：不割野生作物，不踩自己的田

- **`harvest_crops` 默认跳过野生作物。** playtest 11 里让它“收农作物”，它在半径 8 格内割了 7 株，只得到 2 颗种子，玩家当场看穿它割的是野草。对账后确认：野生黑麦只有约三分之一的概率掉一颗种子，永远不出麦子。现在默认不动野生的，并在结果里写明“另有几株野生的没动”；确实想割可以显式打开。
- **没熟不收。** 黑麦和南瓜都要长到第 7 阶段才算熟，提前割只有种子、没有粮食。
- **走上耕地自动蹲下。** 身体直接走上去会把耕地踩回泥土，早期它一路踩坏自己刚翻的地。
- **不在田里和田正下方挖矿。** 有一次它去找硝石，从田里往下打井，九格田只剩一格。现在耕地和玩家建筑一样受保护，挖不动。
- **浇水要先挖沟。** 往敞口的格子倒水会漫开冲毁作物，工具会拒绝；四面都是实心的坑才允许倒。这个做法是玩家提出来的。

### 9. 身体的几个数字

| 项目 | 数值 | 原因 |
| --- | --- | --- |
| 攻击、摔落、火焰抗性 | 各 20 | 继承来的默认值是攻击 10、摔落 7.5，比一只狼还不耐打；20 相当于 21 级玩家，受到的伤害直接减半 |
| 护甲 | 背包里的护甲直接生效 | 引擎的穿戴组件不对非玩家角色开放 |
| 被打还手 | 持续 12 秒；目标跑出 20 格就放弃；血量低于 30% 不打；从不对玩家还手 | 逃生类本能（岩浆、溺水、着火）优先于还手 |
| 自动拾取 | 身边约 2.6 格 | 挖完不用专门去捡 |
| 独自远行 | 离所有玩家超过 40 格时启用，回到 32 格内停用 | 游戏只在玩家周围加载地形和刷新生物；它走远后要自己维持周围的地形和生物，否则读到的全是空气 |
| 找方块的最远距离 | 64 格 | 这是引擎保留地形的边界，不是模组自己设的上限 |
| 死亡不掉落 | 三档：关 / 仅守护灵（默认）/ 全服玩家 | 应玩家要求加入（v0.8.6 起，v0.9.0 扩成三档） |

## 试玩驱动的迭代

这个模组主要是靠一轮轮实际试玩改出来的。每一轮：玩家装上新版去玩 → 把游戏日志 `Game.log` 交回来 → 在日志里找到每条抱怨的真正原因 → 修改并补测试 → 发下一版。编号的试玩到 v0.12.1 为止共 16 轮（playtest 1～16）。

几个有代表性的例子：

| 试玩 | 玩家看到的问题 | 找到的原因 | 修改 |
| --- | --- | --- | --- |
| 4 | 挖矿起不了步，向玩家讨石头 | 自己设的 6 秒工具门槛挡住了徒手挖花岗岩（14 秒）这条正常起步路线 | 门槛改为 16 秒（v0.8.5） |
| 7 | “我想让他挖个矿怎么这么难呢” | 人物身高占两格，挖下行楼梯时目标列只挖开两格，头卡在岩石里；日志里八次下矿全部失败 | 目标列挖空三格；用“全实心岩石里连下 60 层不卡”的模拟测试守住（v0.9.7） |
| 11 | 让它收庄稼，它割了一片野草 | 把野生黑麦当成庄稼 | 默认跳过野生作物并在结果里说明（v0.11.2） |
| 12 | “我让你用木板盖！”背包里有 82 块木板却说没建材 | 判断“这格方块能不能挖”的名单被拿去判断“这格背包物品能不能用”，木板正好在名单里 | 两份名单分开；汇报改为按真实结果（v0.11.3） |
| 13 | 怎么潜行都打不到鸟 | 鸟看见“捕食者”就飞，守护灵被算作捕食者 | 生物类别改为“鸟”（v0.11.5） |
| 14 | “你一直在你盖的房子里转圈圈” | 站在屋里砌墙盖顶，把自己封在里面 | 墙和屋顶从屋外放（v0.11.6） |
| 16 | “我说的是传送”，连续被拒 | 给模型定的传送限制把玩家的直接指令也挡了 | 玩家亲口要求时跳过限制（v0.12.1） |

过程里的两条经验：

- **先核对版本号。** playtest 13 和 15 交回的日志其实是上一版的，导致在错误的前提下找了两轮原因。之后规定进游戏后日志第一行必须对得上要测的版本。
- **守护灵自己的复盘常常比报错信息准。** playtest 16 里它卡死时自己说的是“工具仍被编号 74 的残留任务锁住：状态显示没有运行，但任何新动作都会被拒绝”，和后来在代码里找到的原因一致。

## 怎么验证

- **单元测试**：v0.13.0 共 286 个，在 Linux 上运行。不依赖游戏引擎的部分（寻路、图纸几何、弹道、计划清单、看田的决策等）都单独拆出来测。检验测试本身有没有用的办法是故意把代码改回出错的样子，看测试会不会变红。
- **工具选择基准 ToolBench**：把固定的场景交给真实的模型，考它会不会选对工具，用的是和游戏里完全相同的系统提示词。v0.13.0 在 53 个用例上选对率 95.6%，三次采样至少对一次的比例 98.1%（记录在 `benchmark/history.csv`）。
- **实机试玩**：见上一节。v0.13.0 新增的弓和自动看田，目前仓库里还没有对应的试玩记录。

## 环境与构建

- 游戏：Survivalcraft 联机版 2.4（SurvivalcraftAPI 1.44+）
- 构建：.NET 10，Linux / Windows 均可；运行需要 Windows 端的游戏本体
- 构建时用 `SurvivalcraftDir` 指向游戏 DLL 所在目录：

```bash
dotnet build -p:SurvivalcraftDir=/path/to/sc-libs/
dotnet test  -p:SurvivalcraftDir=/path/to/sc-libs/
```

打包成可安装的模组文件（需要 PowerShell `pwsh`）：

```bash
SURVIVALCRAFT_DIR=/path/to/sc-libs/ ./build-netmod.sh
# 产物：artifacts/SurvivalcraftGenius.netmod，放进游戏的 NetMods 文件夹
```
